# Folder map

What every top-level folder and file is, and which ones are yours. Two rules cover most of it:

- **Yours** (git ignores them; an update never touches them): your data files in the root, `local/`, `uploads/`, `work/`, `logs/`.
- **Core** (git tracks them; an update replaces them): everything else. Change behaviour through `local/` (see [local.md](local.md)) so your changes survive updates.

## Project root

| Path | What it is |
|---|---|
| `start` | One-step start (`./start`): dashboard, browser, steward, and the Underthread icon. The work is in `tools/start.py` |
| `server.py` | The dashboard. `python3 server.py` (env `PORT`, `NO_LOOPS=1`, `--demo`) |
| `stateutil.py` | The command line every teammate uses (`python3 stateutil.py …`); also `import stateutil` for scripts |
| `make_agents.py` | Rebuilds `.claude/agents/*.md` and the steward's dispatch table from `roster.json` |
| `manager.md`, `policy.md`, `team.md`, `CLAUDE.md` | Read by the steward and the teammates on every run |
| `README.md`, `README.zh-CN.md`, `CHANGELOG.md`, `LICENSE`, `VERSION` | The usual |
| `*.example.json` | The seeds a fresh install copies: `config.example.json`, `roster.example.json`, `state.example.json` |
| `core.manifest.json` | Every core file with its checksum (written by `tools/release.py`), so updates can tell your edits from ours |
| **Your data** (not in git) | `state.json` (cards, chat, schedules), `archive.json`, `inbox.jsonl` (your clicks for the steward), `config.json`, `roster.json`, `manager-handoff.md`, `push_subs.json` / `vapid.json` (phone push keys), `secrets_meta.json`, `feeds.json` (connected mailboxes and where the collector is; the passwords are in the keychain, see [feeds.md](feeds.md)) |

The data files stay in the root on purpose: scripts and extensions that read them by that path keep working across every update.

## Folders

| Folder | What it is |
|---|---|
| `core/` | The state store and everything behind `stateutil.py`: paths, store, items, asks, chat, schedules, config defaults, data migrations (`core/migrations/`), extension loading, token usage (`usage_roll.py`), the mail feed collector (`core/feeds/`) |
| `api/` | The server code: `router.py` (route + action tables), `routes/` (one module per feature), `http.py`, `loops.py` (background threads), `ctx.py` |
| `web/` | The page. Plain HTML, CSS and JavaScript, no build step (below) |
| `roles/` | One rule file per teammate (`roles/<id>.md`); your own rules go in `local/roles/` |
| `templates/`, `presets/` | Role templates for the 招聘市场 and whole-crew presets (`tools/preset.py`) |
| `tools/` | Command-line tools: `start.py` (+ `app/icon-1024.png`, the icon's artwork), `update.py`, `release.py`, `bak.py`, `new_role.py`, `preset.py`, `ensure_server.py` / `keepalive.sh` / `install_service.sh`, `webpush.py`, `comfy.py`, `avatar_sizes.py`, `statusline.py`, `demo.py`, … |
| `tests/` | `python3 tests/run.py quick | unit | api | e2e | upgrade | all` |
| `docs/` | Guides: [setup-guide.md](setup-guide.md), [architecture.md](architecture.md), [custom-crew.md](custom-crew.md), [extensions.md](extensions.md), [local.md](local.md), [phone-and-push.md](phone-and-push.md), [troubleshooting.md](troubleshooting.md), this file |
| `avatars/` | Teammate pictures: yours, git-ignored like `roster.json`. Defaults ship in `avatars/seed/ut/` (preset roles in `presets/<name>/avatars/ut/`) and are copied in when missing, never over yours |
| `.github/` | CI, issue templates, CONTRIBUTING, SECURITY, CODE_OF_CONDUCT |
| `.claude/` | `settings.json` ships; `agents/` is generated by `make_agents.py`; `agent-memory/` and `settings.local.json` are yours |
| **Yours** | `local/` (your rules, extensions, backups), `uploads/`, `work/` (one folder per card), `logs/` |

## web/

| Path | What it is |
|---|---|
| `index.html` | The page shell. The server adds `?v=<content hash>` to every file and writes the import map; never write `?v=` by hand |
| `main.js` | The one module entry: imports the page scripts in order |
| `sw.js`, `manifest.webmanifest` | Service worker (push) and the home-screen app manifest; they stay at the top so their scope is the whole site |
| `js/` | Page scripts: `app.js` (wires everything up and boots), `mobile.js` (phone layer), feature scripts (`home.js`, `widgets.js`, `team.js`, `md.js`, …), and the modules in `js/core/`, `js/views/` (`views/pages/` one per page) and `js/phone/` |
| `css/` | Stylesheets: `css/style/` and `css/mobile/` are the two main sheets cut into sections (file-name order = cascade order); the others are one file per skin, texture or feature (`theme-ut.css`, `texture-knit.css`, `widgets.css`, …) |
| `icons/` | Favicons and app icons |
| `fonts/`, `brand/`, `knit/`, `leather/`, `art/` | Fonts, wordmark, texture images, theme art |

Old addresses keep working: `/static/app.js`, `/static/skin-ink.css`, `/static/core/…` and the other pre-0.2 paths are answered with the file from its new folder, and an extension's `"after"` / `"drop"` anchor or a `local/web/` override written with an old name still applies (`api/routes/web.py` `MOVED`).
