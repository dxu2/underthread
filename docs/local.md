# Your own layer: `local/`

Everything git tracks in this repository is **core**. An update may replace any core file. Your own changes live in
**`local/`**, which git ignores and updates never touch. Programs and the steward read core first and `local/` after it;
where they differ, local wins. Nothing writes a core file at runtime: `make_agents.py`, adopted lessons, hiring, transfers
and team presets (`tools/preset.py`) all write here, and make the folder when it is missing. Backups keep going to the
folder that already holds them (`.backups/` on an install that made backups before it had `local/`, else `local/backups/`).

```
local/
├─ manager.md        the steward's own notes (your schedules, people, machines); read right after manager.md
├─ dispatch.md       the dispatch table, generated by make_agents.py from roster.json
├─ CLAUDE.md         imported at the end of CLAUDE.md
├─ team.md policy.md read after the core files of the same name (a team preset writes its own here)
├─ roles/<id>.md     your rules for a role; adopted lessons, hiring, transfers and team presets write here
├─ web/              served at /static/, ahead of web/ (a file here overrides the core file of the same name)
├─ ext/<name>/       extensions: ext.json + server_ext.py / stateutil_ext.py with register(R) + web/ (docs/extensions.md)
└─ ext.json          the old way to add web files (until 0.3.0; put them in an extension's ext.json instead)
```

- **Rules.** `make_agents.py` lists both layers in every agent file: `roles/common.md`, `local/roles/common.md`,
  `roles/<id>.md`, `local/roles/<id>.md` (missing files are skipped). The dashboard's 灵魂 viewer shows both.
- **Web.** `server.py` adds each extension's `web` files (and the old `local/ext.json`) to the page and gives every `/static/` file a
  `?v=<content hash>` (scripts through the page's import map), so a changed file, a `local/web/` override included, always gets a new URL.
  A `local/web/` copy of a core page script is loaded as an ES module (strict mode), like the core file.
  `style.css` and `mobile.css` are cut into sections (`web/css/style/NN-section.css`, `web/css/mobile/...`, file-name order = cascade
  order): `local/web/css/style/<same name>` replaces one section, a new `NN-name.css` slots in by its number, and a whole
  `local/web/style.css` (or `mobile.css`) still replaces the whole sheet.
- **Extensions.** `local/ext/<name>/` with an `ext.json` manifest registers endpoints, actions, card kinds, scheduled jobs,
  health lines, `stateutil.py` commands and page files through the extension registry; see `docs/extensions.md`. A broken or
  mismatched extension is skipped with the reason on `/api/ext`; it never takes the dashboard down. A folder without
  `ext.json` loads the old way (`register(module)`, `CLI_EXT` / `SET_AGENT_HOOKS` / `UPSERT_HOOKS` / `EXT_GET`) until 0.3.0.
- **Another location.** Set `UNDERTHREAD_LOCAL=/path/to/layer` to keep the layer outside the checkout.
- **Config.** `config.json` keys used by the layer: `legacy_headers` (extra request-guard header names, for pages opened
  before a rename) and `github` (`cred_file`, `user`, `repo` for the token check in 设置).

`core.manifest.json` lists every core file with its sha256 (`python3 tools/manifest.py` writes it), so an install that is
not a git checkout can still tell which core files it changed.
