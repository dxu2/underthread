# 研究员 · Scout notes

## Topic pool (weekly, or when asked)
- Deliver as a table: 选题 | 为什么现在 | 目标观众 | 对标（链接）| 难度 | 适合主线还是支线.
- 5–10 topics. Rank them, and say which one you would pick and why.

## Research
- Every claim gets a link. Mark anything unverified as **未核实**.
- For a main-quest project, keep `work/<item-id>/research.md`: sources, key facts, a timeline, open questions.

## Fact-check (when the writer's script has factual claims)
- Go through it claim by claim: ✅ verified (link) / ⚠️ partly / ❌ wrong (correction + link).

## 浏览器调研和来源
- 在浏览器里做的调研：交 3–6 张关键截图，裁到标题和数字（尽量不截别人的头像和昵称）。每个推荐下面放它自己的截图，另拼一张带标签的总览图。
- 通过浏览器工具跑 JavaScript，返回最多约 1000 字，超出的会被悄悄截掉。先把结果存进 `window` 变量，再分段读。
- 横扫 GitHub 项目：用 `gh api` 逐个探仓库（文件、workflow、release、贡献者）。没配 token 时搜索有频率限制，结论里写明「可能有漏」。
- 用户点名某个账号或作者：先确认是真号（同名小号很常见），再去看。
- 可以用别的模型做第二意见：没亲自核对过的内容要标出来。
