# Changelog

What changed in Underthread, newest first. Underthread is developed in the open from the author's daily use; a few features that depend on private artwork or aren't ready for others yet are left out.

Versions follow [semantic versioning](https://semver.org) and the `VERSION` file. Every version has the same four parts, and `tools/release.py` refuses to tag a version whose section is incomplete:

- **Added**, **Changed**, **Fixed**: what a user would notice (write "Nothing." when a part is empty).
- **Upgrade notes**: four lines, always present:
  - `Migrations:` the numbers of the new steps in `core/migrations/` (or `none`);
  - `New config keys:` each new key in `core/config.py` with its default, in backticks (or `none`);
  - `Extension API:` `unchanged`, or what changed for `local/ext/` and `local/web/`;
  - `Manual steps: none`. A change that needs a manual step does not go into a minor or patch version.

Work in progress goes under `## Unreleased`; the release renames it to `## [X.Y.Z] - YYYY-MM-DD`. Sections dated before 0.1.0 are from before versioning.

### Added
- **Mail feed (Settings → Connections)**: a new 连接 / Connections tab links a Gmail account with an app password (IMAP, read-only: it never sends, deletes, archives or marks mail). Off until you connect. The server then checks every 5 minutes (1 / 5 / 15 / 30 / 60, with an on/off switch, **Fetch now**, **New password** and **Disconnect**) and writes one headers-only `kind: feed` entry to the steward's inbox when there is new mail: one row per thread, threads seen before marked `again`, an unacknowledged entry merged into the next, old mail never replayed. An optional tool-less classifier (`claude -p`, haiku) sorts each mail into needs_user / can_draft / fyi with a one-line reason and falls back to headers when it is off or fails; every field is cleaned and marked untrusted. The password goes to the macOS keychain (or, after you confirm, a 0600 file for Linux or a locked keychain) and never into config, `feeds.json`, the inbox, logs or a command line. The steward's rules for feed entries are in `roles/manager.md` → Feeds (quiet for two weeks, cards only for needs_user, drafts only). Slack is listed as coming soon. See [docs/feeds.md](docs/feeds.md).
- **Folder map**: [docs/layout.md](docs/layout.md) says what every top-level file and folder is and which ones are yours (git ignores them, updates never touch them).
- **One-click updates and rollback**: Settings → System → Updates shows your version, checks once a day for a newer release (`git fetch --tags`; `update.check: false` in `config.json` turns that off) and lists what it brings. **Update** first runs the new version in a temporary git worktree on a copy of your data and `local/` (migrations, `make_agents.py`, a server start), then snapshots your data to `local/backups/update/`, moves the install to the new release (fast-forward only), runs the migrations and `make_agents.py`, and restarts the dashboard; if the new server does not answer within a minute it goes back by itself. **Go back** returns to the version before (the code only: minor versions only add to the data, which the old code still reads). It waits while a voice call is on or a teammate is working. Your own edits to core files are saved as a patch and put back on top; if they no longer fit, nothing changes and you choose (keep them and stay, or `--discard-mine`, which keeps the patch). Untracked files in the way of a new file are moved aside, never deleted. The steward gets an `update_done` inbox entry (with a note when `manager.md` or `roles/` changed). Command line: `python3 tools/update.py check | status | apply [--to REF] | rollback [--data]`. Git installs only; a zip install is told to clone instead. `tests/upgrade/test_upgrade.py` updates a clone of the previous release (fixture board, a changed setting, a `local/` rule and extension, an edited core file) to this commit, checks everything survived, rolls back and checks again.
- **Backups in one place**: `tools/bak.py save <tag> <file>...` copies a file git does not track (state, config, roster, handoff notes, anything in `local/` or `.claude/agents/`) to `local/backups/bak/` (`.backups/bak/` without a `local/` folder) before you change it; `list` and `restore` find it again, and a tag already used for a file is refused instead of overwritten. Files git tracks need no copy: git is their backup. `tools/bak.py sweep` lists the old `<file>.bak*` copies scattered through an install and, with `--apply`, moves them out to `~/UnderthreadBackups/` (`unsweep` puts them back); `tests/unit/test_bak.py` fails if one turns up under `web/` or `templates/`.
- **Extension registry**: an extension in `local/ext/<name>/` with an `ext.json` manifest (`"api": 1`) can add GET and POST endpoints (`R.route`), `/api/action` kinds (`R.action`), card kinds (`R.card_kind` or `card_kinds` in the manifest; `stateutil.py --kind` accepts them), scheduled jobs that show up on the 定时 page where you can pause them, change their time or run them now (`R.job`), lines on `/api/health` (`R.health`), and its own page scripts and styles served from its `web/` folder. An extension written for another API number or Underthread version is skipped with one card on the board explaining why, and removing an extension leaves a working board. `GET /api/ext` lists the extensions, card kinds and jobs. In the page, `App.ext` (`web/ext.js`) adds home widgets, card kind labels, tool pill buttons and 系统状态 rows; the nine core home widgets are registered the same way, and a widget new to your board appears on the home once (removing it sticks). The 系统状态 panel lists an extension that did not load or still uses the old way. See `docs/extensions.md`.

### Upgrade notes
- Migrations: none (browser side: `web/js/lsmigrate.js` step 2 maps `rt.texture` `knit2` → `knit1`, `leather2` → `leather1`)
- New config keys: `update.remote` = `""` (the git remote to update from; empty = the branch's upstream, else `origin`), `update.check` = `true` (look for a new release once a day), `feeds.interval_min` = `5`, `feeds.max_per_poll` = `30`, `feeds.snippet_chars` = `120`, `feeds.primary_only` = `true`, `feeds.classifier` = `"auto"`, `feeds.classifier_model` = `"haiku"` (the mail feed; its own data is the new `feeds.json`, created on first connect, so `state.json` needs no migration), `hire_welcome.wait_avatar_min` = `0` (minutes the new-teammate welcome waits for a picked avatar after a placeholder one), `image.backend` = `"auto"`, `image.comfy_workflow` = `""`, `image.comfy_prompt` = `"6.text"` (tools/image.py: which picture backend, and for ComfyUI the workflow and the node input that takes the prompt)

## [0.1.0] - 2026-11-14

### Added
- **Seamless data upgrades**: `state.json` carries a schema number (`meta.schema`) and ordered migrations in `core/migrations/` run on the first read after an update, with the old file saved to `local/backups/migrate/` first. Config defaults live in `core/config.py` and are merged at read time, so new settings need no edit to your `config.json`; `stateutil.py schema` and `stateutil.py config show` show where things stand. - **Versions and releases**: a `VERSION` file, this changelog's fixed four parts, and `tools/release.py X.Y.Z`, which checks the tree, the tests, the migrations and the changelog before it writes `core.manifest.json`, commits and tags. The compatibility promise is in `CONTRIBUTING.md`.
- **Your own layer in `local/`**: your rules, manager notes, extensions and web overrides live in `local/` (or `$UNDERTHREAD_LOCAL`), which updates never touch. Extensions: `local/ext/<name>/stateutil_ext.py` (`CLI_EXT`, `SET_AGENT_HOOKS`, `UPSERT_HOOKS`) and `server_ext.py` (`EXT_GET`); `local/web/` files win over `web/`, and `local/ext.json` adds or drops web files. `core.manifest.json` lists every core file with its sha256.
