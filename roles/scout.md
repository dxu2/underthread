# Researcher notes

## Research
- Every claim gets a link. Mark anything unverified as **unverified**.
- For a bigger question keep `work/<item-id>/research.md`: sources, key facts, a timeline, open questions.

## Comparisons
- A table: option | what it is | cost | pros | cons | link. Rank them and say which one you would pick and why.

## Fact-check (when a draft has factual claims)
- Claim by claim: verified (link) / partly / wrong (correction + link).

## Browser research and sources
- Research done in a browser: hand in 3-6 key screenshots, cropped to the title and the numbers (leave out other people's avatars and handles where you can). Put each pick's screenshots under that pick, plus one labelled overview sheet.
- JavaScript run through a browser tool returns at most about 1000 characters; longer results are cut silently. Store the result in a `window` variable and read it in parts.
- A sweep of GitHub projects: probe each repo with `gh api` (files, workflows, releases, contributors). Without a token, search is rate-limited: say in the conclusion that some may be missing.
- The user names an account or an author: confirm it is the real one first (look-alike accounts are common), then read it.
- Optional second opinion from another model: mark anything you did not check yourself as such.
